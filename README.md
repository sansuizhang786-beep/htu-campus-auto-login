# 河南师范大学校园网自动登录

河南师范大学校园网 Windows 自动登录工具，支持开机及睡眠恢复后自动认证，联网成功后自动退出。提供图形化配置界面，使用 Windows DPAPI 加密保存密码，无需安装 Python 或浏览器扩展。

认证入口预设为 `http://1.1.1.1/`，使用校园网账号。**每次登录 Windows 或从睡眠/休眠恢复后运行一次，确认联网成功后自动退出，不常驻，也不监测后续断线。**

## 功能

- 图形化配置校园网账号、认证入口和自动登录。
- 当前 Windows 用户登录时自动运行，睡眠或休眠恢复后再次运行。
- 使用独立的隐藏 Edge 完成原生网页认证，保留网关跳转参数。
- 区分校园网络与手机热点，结合认证页面状态和 HTTPS 内容确认联网。
- 登录成功后关闭临时浏览器并退出；连续三次提交后未能确认联网也会结束本次运行。
- 使用 Windows DPAPI 加密保存密码，可查看状态、停止当前登录或关闭自启动。

## 运行环境

- Windows，已安装 Microsoft Edge。
- .NET Framework 4.7.2 或更高版本。
- 电脑已连接河南师范大学校园 Wi-Fi 或校园网网线。

## 从源码构建

克隆或下载本仓库源码，在项目目录打开 Windows PowerShell 并运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
```

构建后得到 `HTUAutoLogin.exe`。运行时将它与仓库内的 `HTUAutoLogin.exe.config` 保留在同一固定目录，然后双击程序。

## 首次使用

1. 将 `HTUAutoLogin.exe` 和 `HTUAutoLogin.exe.config` 保留在固定目录，直接双击程序。
2. 认证地址保留 `http://1.1.1.1/`，填写校园网账号与密码。无需给账号添加运营商后缀。
3. 在 Windows 连接 `HTU_Student` 后点击“测试登录”。真正验证认证需在连接校园网但尚未认证时进行；手机热点或家庭网络的联网不计作校园网认证成功。
4. 点击“保存并启用自动登录”。程序加密保存密码，在当前 Windows 用户的启动文件夹中创建快捷方式，同时安装睡眠恢复触发，并立即启动本次自动登录。
5. 可以关闭设置窗口。以后**每次开机登录当前 Windows 用户或从睡眠/休眠恢复后**，程序静默运行，等待网络就绪并在需要时登录；**确认联网成功后，自动登录进程自行退出**。

电脑需要先连接 HTU_Student / HTU / HTU_5G 或校园网网线。Wi-Fi 的“自动连接”由 Windows 管理；本程序完成的是连接后的网页认证。它不自行切换网络，不在 Windows 用户登录之前运行，也不使用每日固定时间的计划任务；同一天重新登录 Windows 也会启动一次。

双击程序打开的是设置窗口，方便修改账号或查看状态，需要手动关闭。开机启动时不会打开此窗口，成功后会结束自动登录进程及其创建的临时浏览器。

## 运行行为

- 自动登录启动后缓冲 0.5 秒即识别网络。热点或其他 Wi-Fi 不会被当作校园网已登录；程序会等待校园网连接。
- 使用独立、隐藏的 Edge 打开 `http://1.1.1.1/`，必要时通过学校官方说明推荐的普通 HTTP 页面 `http://www.edu.cn/` 触发认证跳转，再尝试保存的入口。保留跳转中的动态参数，不只打开认证服务器根目录。
- 只有来源为 `http://1.1.1.1` 或 `http://10.101.2.194:6060`、标题包含“河南师范大学”、且出现已知可见表单时，才填写账号密码并点击原生登录按钮。普通网站从不会接收账号密码。
- 页面上的原生 JavaScript 负责认证提交；程序没有猜测或硬编码其它学校的 Dr.COM/锐捷接口。
- 普通 HTTPS 网站需要返回预期页面内容；读到预期标题即可结束本次内容读取，不等待后续正文，读取上限仍为 32,768 个字符。不再以微软 NCSI 检测页面作为成功依据。HTTP 200、空白页或标题改变不会单独被当成认证成功。
- 发现登录表单时优先完成认证。跳过认证需要同时确认校园网络、网关有响应、没有待认证表单、普通 HTTPS 网站可访问；提交后的成功判断还要求登录表单已离开，并重新检查网络未切到热点。
- 确认已联网或登录成功后保留最终状态，关闭本次创建的临时浏览器并退出自动登录进程。之后不再轮询网络，也不会自动断线重连；下次登录 Windows 或睡眠恢复时重新启动。已有自动登录进程时不并行提交。
- 网络未就绪或认证页面未取得时，前 5 次检查结束后间隔 2 秒重试，第 6～10 次间隔 5 秒，之后间隔 15 秒；检查自身的耗时另计。认证页加载期间每 0.2 秒检查表单是否就绪。其他执行异常逐渐延长重试，最长 5 分钟。
- 每次提交之后未能确认联网，都会计入失败次数，包括响应超时。失败后间隔 2 分钟、4 分钟再试；连续 3 次失败会结束本次运行。下次登录 Windows 时仍会自动启动，也可核对设置后点击“保存并启用自动登录”立即重试。
- 验证码、未知页面或未适配的跳转地址不会自动填写密码。请手动登录并提供不含账号密码的认证地址，以便进一步适配。
- “立即自动登录”使用已保存的账号开始一次自动登录；“停止本次登录”只停止本次运行；“关闭自启动并停止”同时移除自启动快捷方式与睡眠恢复任务。

## 本地文件

配置和日志位于 `%LOCALAPPDATA%\HtuAutoLogin`：

| 文件 | 用途 |
| --- | --- |
| `settings.xml` | 认证地址、账号、Windows DPAPI 加密后的密码 |
| `status.txt` | 最近一次自动登录状态，成功退出后保留成功结果 |
| `log.txt` / `log.previous.txt` | 运行摘要，约 1 MB 轮转，不记录账号密码或网页请求正文 |

密码只可由同一电脑上的同一 Windows 用户解密。复制程序到其他电脑后需重新填写。网页认证仍按学校提供的 HTTP 页面工作；本地加密不改变学校的传输协议。

登录自启动快捷方式为当前用户启动文件夹里的 `HTU-Campus-AutoLogin.lnk`，目标参数为 `--background`。睡眠恢复任务为任务计划程序中的 `HTU-Campus-AutoLogin-Resume-<当前用户 SID>`，订阅 System 日志的 Power-Troubleshooter 事件 1，同样运行本目录程序的 `--background`。

恢复任务只使用当前已登录用户的普通权限，不保存 Windows 密码；允许电池供电和网络尚未就绪时运行，不主动唤醒电脑，不设置循环认证计时。移动程序位置后应重新点击“保存并启用自动登录”。

若不再使用，先点击“关闭自启动并停止”，退出设置窗口，再删除程序目录。若也要移除保存的凭据，另行删除上述配置文件夹。

## 开发与验证

源码：`Program.cs`（窗口）、`AppSupport.cs`（配置和自启动）、`Core.cs`（认证）、`Worker.cs`（后台）。

```powershell
.\Build.ps1   # 使用 Windows 自带 .NET Framework C# 编译器构建
.\Test.ps1    # 本地模拟表单、来源限制、DPAPI 与后台启停测试
.\Test.ps1 -TaskOnly  # 只验证系统任务注册与无网络访问的模拟启动
```

`Tests.cs` 只使用虚构账号，测试存储重定向到项目内的 `test-output`，并使用独立的后台进程标识以免干扰正常运行的程序。任务测试使用唯一的临时任务名称，仅启动写入项目内标记文件后退出的模拟程序，并在结束时删除任务。测试不会启用真实认证自启动，不会注销校园网，也不会发送真实登录请求。`GuiSmoke.ps1` 是可选的界面离屏渲染检查。

2026-10-07 的本地验证记录为 65 项检查通过，覆盖来源限制、DPAPI、后台退出、重试间隔、临时浏览器清理以及恢复任务注册等行为。这些检查使用模拟认证页面，不能代替不同校区和网关下的真实联网验证。认证页面发生变化时可能需要重新适配。

命令行参数：

- `--background`：使用已保存配置静默等待网络并尝试认证，确认联网成功后退出。保留此参数用于开机快捷方式。
- `--once`：使用已保存配置检查一次。联网或确认登录成功返回 0，认证未完成返回 1，没有配置返回 2。Windows GUI 程序不输出控制台文本。
- `--install-startup`：只安装/修复登录快捷方式和睡眠恢复任务，不读取校园账号、不启动认证。供原位置升级时使用。
